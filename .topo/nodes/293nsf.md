## [F003] Concurrent membership changes can restore revoked ownership or remove every owner

スキャン: 44dbfab6-0d90-475d-b2a3-4df6534779e5

Membership PUT and DELETE authorize against a snapshot and commit in a later transaction. An in-flight self-owner PUT can recreate a removed owner, and concurrent demotions/removals can leave a workspace without any owner.

  "summary": "`members()` authorizes the caller and reads owners in one completed batch. `put()` then awaits GitHub and checks the stored snapshot before a separate unconditional `upsert_member()`; `remove()` similarly checks the snapshot before a separate delete. Neither SQL nor schema enforces current caller ownership or preservation of one owner at commit, so transactions around individual batches do not protect the invariant across them."
}

Resolve external GitHub identity before final authorization, then enforce current caller ownership and the final-owner invariant atomically with every membership update/removal. Use guarded SQL or a membership/authorization revision, fail stale authorization predicates, and retry failed concurrent updates without relying on an earlier owner-count snapshot.
