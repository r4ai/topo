## [F014] Recapturing supplied metadata can execute shell commands in the scratch GUI

スキャン: 44dbfab6-0d90-475d-b2a3-4df6534779e5
指摘番号: F014
findingId: csf_e513ab3895cba026305697c1
occurrenceId: occ_2e9de3fc578bbd5d5ac4fe68

共通原因: promo-recapture
元データ: /Users/r4ai/.codex/state/plugins/codex-security/scans/topological-todo/a11e0dc222073580267e9db95182657c54532148_20261003T004741Z_cj30b2n2/findings.json

An identifier in `promo/assets/data.json` can contain a newline that becomes a `sh` command when an operator runs `MOVES_ONLY` with the separately patched capture GUI. This executes with the operator's privileges.

## 根本原因

    "dedup-0004-8-capture-id-trust",
    "dedup-0004-8-capture-id-interpolation",
    "dedup-0004-8-capture-script-write",
    "dedup-0004-8-capture-line-interpreter"
  ],
  "summary": "`MOVES_ONLY` reads a previous JSON metadata bundle and accepts `previous.ids` without the node-ID validation used by production operations. `frameConnect` and `select` interpolate those values into commands; `lines.join()` writes embedded line separators unchanged. The patched GUI reads that file through `TOPO_PROMO` and dispatches each line separately. A metadata newline can therefore introduce the driver's intentional `sh` capability, which invokes `/bin/sh -c`. The missing boundary is between identifiers treated as data and the executable capture program. The assigned source explicitly distinguishes the !MOVES_ONLY guard on intentional generated shell commands from embedded lines originating in metadata; that guard does not inspect the injected lines."
}

## 修正方針
Validate every metadata identifier against the production NodeId grammar before constructing commands. Prefer a structured command format with typed arguments instead of newline-delimited interpolation. Recapture mode should also reject command types, such as sh, that its generated workflow does not require.

## [F040] Imported capture IDs can inject shell commands into recapture scripts

スキャン: 44dbfab6-0d90-475d-b2a3-4df6534779e5
指摘番号: F040
findingId: csf_a60ee7c10b28e9a37252b873

重要度: medium
共通原因: import-authorization
元データ: /Users/r4ai/.codex/state/plugins/codex-security/scans/topological-todo/a11e0dc222073580267e9db95182657c54532148_20261003T004741Z_cj30b2n2/findings.json

MOVES_ONLY recapture imports identifiers from an asset JSON bundle and interpolates them into newline-delimited commands. The optional patched GUI executes injected shell-command lines with the capture operator's authority.

## 根本原因
{
  "evidenceRefs": [
    "imported-ids",
    "reused-ids",
    "script-ids",
    "script-write",
    "script-parser",
    "script-shell"
  ],
  "summary": "MOVES_ONLY assigns previous.ids from parsed promo/assets/data.json without validating node IDs. Those strings enter frame/select/status commands, and lines.join(\"\\n\") creates the script consumed by the capture driver. An ID containing a line terminator can preserve the initial valid frame command and introduce a separate sh line. The opt-in patch splits script.lines() and dispatches sh to /bin/sh -c; data is promoted to commands without a protective boundary."
}

## 修正方針
Validate every imported identifier against the node-ID grammar before constructing scripts and reject line terminators. Use structured commands with validated arguments, and remove shell execution from recapture scripts generated from imported data.
