# Database Design

Cloudflare D1 (SQLite) serves as the persistent store. A workspace graph is compact enough to load entirely into `topo-core::Graph` in memory during writes. The database persists entities, credentials, memberships, node attributes, and an append-only change log without evaluating DAG relationships directly.

## Schema Definition

```sql
CREATE TABLE users (
  id         INTEGER PRIMARY KEY,          -- GitHub user ID (stable across username renames)
  login      TEXT NOT NULL,                -- GitHub login handle (refreshed on sign-in)
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE workspaces (
  id         TEXT PRIMARY KEY,             -- Unique random identifier generated by server
  name       TEXT NOT NULL,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE workspace_members (
  workspace_id TEXT NOT NULL REFERENCES workspaces (id) ON DELETE CASCADE,
  user_id      INTEGER NOT NULL REFERENCES users (id) ON DELETE CASCADE,
  role         TEXT NOT NULL CHECK (role IN ('owner', 'editor', 'viewer')),
  PRIMARY KEY (workspace_id, user_id)
);
CREATE INDEX workspace_members_user ON workspace_members (user_id);

CREATE TABLE tokens (
  id           TEXT PRIMARY KEY,           -- Public handle for listing and revocation
  hash         TEXT NOT NULL UNIQUE,       -- SHA-256 digest of secret token
  user_id      INTEGER NOT NULL REFERENCES users (id) ON DELETE CASCADE,
  workspace_id TEXT REFERENCES workspaces (id) ON DELETE CASCADE, -- NULL grants access across user workspaces
  name         TEXT NOT NULL,
  expires_at   INTEGER,                    -- NULL indicates no expiration
  created_at   INTEGER NOT NULL DEFAULT (unixepoch())
);
CREATE INDEX tokens_user ON tokens (user_id);

CREATE TABLE nodes (
  workspace_id TEXT NOT NULL REFERENCES workspaces (id) ON DELETE CASCADE,
  id           TEXT NOT NULL,              -- Node ID, unique per workspace
  kind         TEXT NOT NULL CHECK (kind IN ('task', 'milestone')),
  title        TEXT NOT NULL,
  status       TEXT NOT NULL CHECK (status IN ('todo', 'doing', 'done', 'dropped')),
  due          TEXT,                       -- 'YYYY-MM-DD' or NULL
  tags         TEXT NOT NULL,              -- JSON array of strings
  depends_on   TEXT NOT NULL,              -- JSON array of prerequisite node IDs
  milestones   TEXT NOT NULL,              -- JSON array of parent milestone IDs
  body         TEXT NOT NULL,              -- Markdown note content
  priority     TEXT CHECK (priority IN ('low', 'medium', 'high', 'urgent')),
  assignee     TEXT,                       -- Assigned actor or NULL
  prs          TEXT NOT NULL DEFAULT '[]', -- JSON array of pull request URLs
  created_at   TEXT,                       -- RFC 3339 UTC timestamp or NULL
  updated_at   TEXT,                       -- RFC 3339 UTC timestamp or NULL
  completed_at TEXT,                       -- RFC 3339 UTC timestamp (set only while status is 'done')
  PRIMARY KEY (workspace_id, id)
);

CREATE TABLE changes (
  workspace_id    TEXT NOT NULL REFERENCES workspaces (id) ON DELETE CASCADE,
  version         INTEGER NOT NULL,        -- Monotonically increasing version per workspace
  user_id         INTEGER NOT NULL REFERENCES users (id),
  token_id        TEXT NOT NULL,           -- Token handle used for write
  token_name      TEXT NOT NULL,           -- Token description at write time
  agent           TEXT,                    -- Writer label from Topo-Agent header
  idempotency_key TEXT NOT NULL,
  ops             TEXT NOT NULL,           -- JSON array of executed operations
  created         TEXT NOT NULL,           -- Mapping of internal references to generated IDs
  created_at      INTEGER NOT NULL DEFAULT (unixepoch()),
  PRIMARY KEY (workspace_id, version),
  UNIQUE (workspace_id, idempotency_key)
);
```

Dependencies and milestone memberships are stored directly as JSON arrays on node rows. This layout preserves the exact sequence order between file round-trips without requiring normalized relational edge tables.

## Data Integrity and Invariants

Relational constraints enforce identity and column boundaries before graph reconstruction. All semantic graph invariants are evaluated in memory by `topo-core::Graph`:
- Target references must resolve to existing workspace nodes
- Node dependency and milestone membership relations must remain strictly acyclic
- Only tasks may belong to milestones
- Pull request references and assignees are normalized into canonical forms

## Transactional Write Flow

Cloudflare D1 executes multi-statement batches transactionally:

1. **Read Batch**: Retrieves caller membership, latest workspace version, existing idempotency key, nodes, and `unixepoch()` in one batch of five statements
2. **Idempotency Verification**: If the idempotency key exists, returns the previously recorded version and created IDs immediately
3. **Optimistic Version Check**: Rejects with `precondition_failed` if an `If-Match` header does not match the active version
4. **Invariant Validation**: Hydrates a `Graph`, applies operations, verifies cycle-freedom, and computes timestamp stamps
5. **Diff Generation**: Computes changed and deleted nodes
6. **Commit Batch**: Inserts the new `changes` record, upserts modified nodes via `ON CONFLICT`, and removes deleted IDs
7. **Collision Handling**: If a concurrent write took the same version or idempotency key, the batch aborts and the whole sequence is recomputed. After three failed attempts the server returns `503 busy`
